# Style Guide

## 目标

把文本写得更像 Qianzhu 本人：
- 有实践感
- 有系统感
- 有成长感
- 能把复杂东西讲成人话
- 不飘，不端，不晦涩
- 有一点松弛和幽默

## 总体气质

更接近这种感觉：

- 真实
- 清醒
- 持续成长
- 有实践感
- 有判断力
- 带一点年轻人的轻松感

不要变成：

- 机构号
- 搬运号
- 过于成熟的导师号
- 纯碎片工具号
- 过度严肃的说明文

## 基本语气

- **第一层是清楚**：先让读者看懂，再谈洞见
- **第二层是判断**：解释之后要有一句值得记住的话
- **第三层是人味**：允许有“我怎么想明白的”“我在哪个场景里踩到这个问题”的痕迹
- **第四层是成长感**：允许出现“我以前怎么想”“我最近才建立起这个直觉”
- **第五层是洞察力**：哪怕写的是一个平常小事，也要继续往下拆到更深一层结构

## 句子层面的硬约束

1. 少用连着出现的抽象名词。
2. 一个段落只做一件事。
3. 每出现一个技术词，尽量补一个生活化解释或对比。
4. 能用“讲明白、讲顺、拆开、跑起来”这类动词，就不要堆“赋能、构建、形成、实现”。
5. 不要把每句话都写成结论句，给读者留出理解过程。
6. 不要把每段都写成“成熟总结”，允许保留一点正在发生的感觉。
7. 能具体就具体，能落回真实场景就落回真实场景。

## 常见降晦涩方法

### 写法 1：先说人话，再说术语

- 差：`模型通过语义表示与对齐机制形成类理解能力`
- 好：`它看起来像懂你，其实是语义表示和对齐一步步叠出来的`

### 写法 2：先给场景，再讲原理

- 差：一上来进入定义和分类
- 好：先说“为什么我们会误以为它真的懂了”，再解释模型机制

### 写法 3：用对比替代堆概念

- RNN：一站一站传话
- Transformer：当前位置直接看全局
- 预训练：学会继续说
- SFT：学会像个助手

### 写法 4：先讲你是怎么碰到它的，再讲你怎么看它

- 差：`最近 Agent 很火，我来分析一下趋势`
- 好：`这两天看了几轮产品和讨论，我最后留下来的不是兴奋，而是一个更具体的问题，这波变化到底先改掉谁的工作方式`

### 写法 5：保留一点成长痕迹

- 差：`我一直都很清楚内容定位应该怎么做`
- 好：`我最近才慢慢想清楚，我更想写的其实不是泛泛的趋势快讯，而是一个普通年轻人怎么在 AI 时代一点点长出来`

### 写法 6：从小事往深处拆

- 差：`最近这个梗很火，大家都在玩`
- 好：`很多看起来荒诞、无厘头、甚至上不了台面的互联网小狂欢，背后其实都藏着非常稳定的传播逻辑`

### 写法 7：别把洞察写成“感想”

- 差：`这件事让我挺有感触`
- 好：`这件事最后留下来的，不只是一个现象，而是一个更具体的提醒`

### 写法 8：概念当入口，不当主角

- 差：`Harness Engineering 是由谁提出的，它包含哪些模块`
- 好：`我不太想把 Harness 写成新概念科普。我更想讲的是，为什么新人真正该练的可能是文档、参考和反馈管理。`

### 写法 9：保留辩证张力

- 差：`这个范式非常重要，大家都应该尽快学习`
- 好：`它可能只是阶段性的脚手架，但阶段性不等于不值得学。`

- 差：`这个开源框架对新人没有用`
- 好：`它可以当心法看，但不要一上来就想着把整套东西搬进自己的项目。框架可以参考，项目必须自己消化。`

## 推荐结构

### A. 学习型/拆解型文章

1. 一个真实困惑或学习触发点
2. 用通俗语言拆概念
3. 抽出 3-7 条真正值得传播的判断
4. 用一句更高层的总结收束

### B. 产品/实践型文章

1. 真实痛点或任务场景
2. 你怎么做、怎么试、怎么改
3. 过程中建立的判断
4. 对别人有什么用

### C. 成长感补法

如果正文已经足够有用，但“作者本人”太弱，就补下面任意一种：

1. 我原来对这件事的误判
2. 我在哪一步踩坑了
3. 我最近才建立起来的一点直觉
4. 这件事为什么会影响我接下来怎么做

注意，只补一层就够，不要把正文拽成日记。

### D. AI Coding / 工程范式反思

如果写 Harness、Agentic Engineering、SDD、BMAD、Vibe Coding 这类概念，优先这么写：

1. 先写作者自己在哪个项目、文档或工作流里碰到类似问题
2. 用人话讲概念的当下价值，不要急着贴定义
3. 加一层清醒判断：哪些东西可能会被模型或平台内化
4. 把最后真正留下来的能力说清楚：拆需求、找参考、写验收、跑反馈、清理文档
5. 结尾落在具体行动视角上，而不是“未来趋势已来”

常用对比：

- `护城河` vs `训练场`
- `新名词` vs `把项目做顺`
- `直接缝合框架` vs `先消化成自己的项目能力`
- `AI 会写代码` vs `AI 不知道当前项目里什么才是对的`
- `看不见的信息` vs `项目里可复用的文档和反馈`

## 平常事物洞察写法

如果题目来自一个日常触发点，比如梗图、刷屏、校园社交动作、产品里的细小习惯，优先这么写：

1. 先写它表面上为什么轻、怪、离谱
2. 再讲你为什么不想轻视它
3. 再往下拆：它暴露的是哪层稳定结构
4. 最后把这层结构变成一个别人能带走的判断

关键不是把小题写大，而是把小题写深。

## 去机构感方法

- 少用完整、过满、过于正确的表达
- 允许出现一点犹豫和判断建立过程
- 允许轻轻吐槽，但不要一直抖机灵
- 少用“我们可以看到”“这给我们的启示是”
- 多用“我更关心的是”“我后来发现”“我现在会更倾向于”

## 短信息流安利文案规范

适用：群聊、朋友圈、X/Twitter 中文流、文章转发配文

要求：
- 每条不超过 100 个汉字
- 只回答三件事：这是什么、适合谁、为什么值得点
- 优先用判断句或问题句开头
- 不要复述大段长文摘要
- 不要用“欢迎阅读我的文章”这类弱开头

推荐骨架：
- `一个判断 + 这篇解决什么问题`
- `一个痛点 + 这篇把它讲顺了`
- `一个反常识 + 这篇给出解释`

## 结尾风格

- 不要硬上价值
- 更适合用“我现在的理解是……”“这也是我最近真正建立起来的直觉”收尾
- 如果要邀请互动，语气要像共学，不像运营话术
- 不要写成“我已经完全想明白了”
- 更适合让读者感觉，这个人还在继续往前走

### 结尾硬规则

1. 结尾要落在一个**具体判断 / 提醒 / 行动视角**上，而不是落在情绪和寒暄上。
2. 如果前面已经出现一句足够有力的话，结尾就该停，不要再往后拖。
3. 禁止用礼貌性互动尾巴冲淡判断，例如：
   - `这也是我最近越来越有感觉的一件事。`
   - `如果你最近也关注这些东西，欢迎和我交流。`
   - `这样的现象，我之后应该还会继续写。`
4. 更好的收法是这种“钉子句”：
   - `而是一个更具体的提醒：互联网里最强的传播，很多时候都不是在说服你，而是在邀请你参与定义自己。`
5. 结尾像把钉子钉进墙里，不像把门轻轻带上。
