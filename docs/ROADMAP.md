# Product Roadmap

这个项目现在收敛为一个单页 `Skill Store`，目标不是做全能平台，而是先把本地 skills 的发现、安装和管理做好。

## 当前产品定义

MVP 只做 5 件事：

1. `Discover`
   像应用商店一样搜索、分类、推荐，先让用户看懂这个 skill 是干嘛的。
2. `Install`
   一键安装到 `Claude Code` 或 `Codex`，默认隐藏目录和配置细节。
3. `Library`
   `Claude Code` 和 `Codex` 分开管理，不混成一张表。
4. `Batch`
   支持批量删除和批量生成标签，优先保证库干净可维护。
5. `Trust Layer`
   明确展示来源、兼容性、是否含脚本、风险提示，再决定装不装。

## MVP 范围

### 必须完成

1. `3009` 默认可访问，并稳定打开当前项目
2. `Discover` 支持本地 catalog 搜索、标签过滤、推荐浏览、分页
3. `Discover` 卡片简介默认收纳为 2 行，详情点击后再在抽屉展开
4. `Claude Code` 与 `Codex` 的安装状态完全分开显示
5. `Library` 只管理本机已安装 skills，只保留删除动作，不再额外设计停用流
6. 支持一键安装到正确目标端，并阻止装到不兼容端
7. 支持单个删除与批量删除
8. 支持智能生成标签，后续用户按标签管理
9. 详情抽屉支持预览 `SKILL.md`、README、信任信息和文件概况

### 暂不放进 MVP

1. GitHub 云端镜像
2. 本地和远端差异同步矩阵
3. 复杂账号体系
4. 在线编辑器
5. 多平台适配到 Claude / Codex 之外的大量生态

## 搜索策略

### V1

- 先把本地发现做好：搜索名称、简介、标签、来源、兼容性
- 搜索结果支持排序和分页
- 标签用于后续管理，不把风险、来源、兼容性硬塞成标签

### V1.5

- 提升推荐逻辑
- 做更好的精选区和分类浏览
- 补“最近安装 / 高信任 / 含脚本提醒”等运营模块

### Phase 2

- 接入外部搜索源
- 优先评估 `Vercel skills` / `find-skills` 作为远端发现入口
- 支持从远端结果一键导入到本地 `Claude Code` / `Codex`

这一步是“扩展发现能力”，不是当前 MVP 的前置依赖。

## 当前开发顺序

### Phase 1: Skill Store MVP

1. 打磨 `Discover / Library` 双视图
2. 修复预览稳定性，保证 `3009` 可访问
3. 补齐分页、搜索、抽屉预览和批量删除
4. 完成 `Claude Code / Codex` 分库安装和管理
5. 打磨标签生成与信任展示

### Phase 2: 外部发现

1. 接入 `Vercel skills` / `find-skills`
2. 设计远端搜索结果卡片
3. 做导入确认与兼容性判断

### Phase 3: 开源准备

1. 去掉个人路径耦合
2. 做首次启动向导
3. 补 README、截图、示例配置
4. 补核心扫描逻辑测试
